# CLAUDE.md — память проекта «Мафия Online»

Каждый этап ведётся в новом чате без истории. **Перед любой работой прочитай этот файл и `PLAN.md`. В конце этапа обнови оба.**

**Следующий шаг — этап 3: веб-клиент (`packages/web`).** Движок, протокол и сервер готовы; набросок этапа — в `PLAN.md`.

## Что это

Веб-игра «Мафия» для компании друзей. Один создаёт комнату, остальные заходят по ссылке с паролем, каждый видит свою роль на своём телефоне, игра идёт на сервере. Только бесплатные зависимости и бесплатные сервисы.

Общение с пользователем, документация, комментарии в коде и сообщения об ошибках — по-русски. Идентификаторы в коде — по-английски.

У пользователя плохой доступ к внешним API: всё должно работать и тестироваться локально. Деплой — отдельный этап, без команды не настраивать.

## Архитектура

Monorepo на npm workspaces (`packages/*`), Windows, Node 22.12+. Рабочая папка — `D:\mafia_web`. Git: ветка `main`, по коммиту на этап.

| Пакет | Что | Статус |
|---|---|---|
| `packages/engine` (`@mafia/engine`) | Чистая игровая логика на TypeScript. Без зависимостей, без браузера, без Cloudflare. | **готов (этап 1)** |
| `packages/protocol` (`@mafia/protocol`) | Общий протокол клиента и сервера: типы сообщений, проверка входящих, коды ошибок, настройки комнаты, коды комнат. | **готов (этап 2)** |
| `packages/server` (`@mafia/server`) | Cloudflare Worker + Durable Object комнаты с WebSocket Hibernation. | **готов (этап 2)**, без деплоя |
| `packages/web` (`@mafia/web`) | Vite + React + TypeScript + Tailwind + Framer Motion, PWA. | каркас (README) |

Принципы:

- **Сервер авторитетен.** Вся логика на сервере. Клиент получает только `viewFor(state, playerId)` и проекции событий — никогда чужие роли, кроме разрешённых случаев (мафия знает своих; мёртвые видят всех, если включено; в финале открыто всё).
- **Движок — чистые функции.** Вход не меняется, возвращается `{ state, events }`. `GameState` — обычный JSON. Вся случайность — от seed (`state.rng`).
- **Анимации строятся на событиях.** У события есть тип, участники, видимость и «скрытный» вид.
- **Всё из сети недоверенное.** Сервер работает только с результатом `parseClientMessage`.

## Как устроен движок (коротко)

- Фазы: `night → day → night → … → ended`. `round` — номер круга.
- Каждая меняющая функция: `begin(state)` (глубокая копия) → правки черновика и `emit(...)` → `finish(ctx)`.
- **Отложенные решения** (`state.pending`): Охотник, Подрывник, Судья. Пока очередь не пуста, действия не принимаются, фаза не меняется, победа не проверяется. Продвигает игру `advance()` в `flow.ts`.
- Роли описаны данными; логика способностей — в `night.ts` по `ability.id` и `ability.step`.
- Каждая сработавшая ночная способность даёт событие `abilityUsed` (видит только применивший). По нему сервер строит личные сцены «Кино».
- **Убийца не раскрывается:** в событии `death` автора видит только он сам (у мафии — чёрная команда). Это касается и Охотника, и Подрывника.
- `viewFor(state, null, { seeAll: true })` — представление ведущего: все роли, журнал целиком и `backstage` (чужие ходы и голоса). Кому его давать, решает сервер.
- Идентификаторы команд (`red`/`black`/`neutral`), причин смерти (`mafiaKill`, …), стадий и прочего намеренно **не совпадают** с id ролей: тесты на утечки ищут в сообщениях строки вида `"doctor"`. Не вводи значений, совпадающих с id ролей.

## Как устроен сервер (коротко)

- Одна комната — один Durable Object (`idFromName(код)`), SQLite-хранилище, всё состояние — один ключ `room`.
- WebSocket Hibernation: объект может уснуть; о соединении известно только то, что в attachment (`{ m: id участника, ip }`). Никакого состояния «на соединение» в памяти.
- Вход — первым сообщением `hello` (токен либо имя и пароль). Одно соединение на участника.
- Каждый обработчик заканчивается `commit()`: номер рассылки `rev`++, перестановка будильника, запись, рассылка. За одно входящее сообщение каждому клиенту уходит не больше одного `room` и одного `game`.
- Стадии сервера поверх фаз движка: `night`, `decision`, `morning` и `evening` (ожидание `ready`), `day`, `ended`. `step` растёт при каждом разрешении. Синхронизация хранится в `room.sync`.
- Ведущий-наблюдатель — участник, которого нет в `room.players`; только он получает `seeAll`. Никогда не расширяй это условие.
- Один будильник на все таймеры: стадия, утро и вечер (15 с), автопередача хоста (2 мин), простой (6 ч).
- `RoomState.v` — версия формата состояния; комната другой версии при загрузке удаляется. Меняешь формат — поднимай `ROOM_STATE_VERSION`.
- Криптография асинхронна: в `onHello` сначала считаются хеши, и только потом читается и меняется состояние — иначе между `await` может вклиниться чужое сообщение.
- Часы: `now()` = `Date.now() + skewMs`; тесты сдвигают `skewMs` и вручную запускают будильник.

## Принятые решения по правилам (этап 1)

Подробно — в README движка, раздел «Граничные случаи».

- **Победа чёрных:** чёрных ≥ остальных живых; пока жив Маньяк — строго больше. Один мафиози против Маньяка — **ничья**. Все мертвы — ничья.
- **Победа красных:** мертвы все чёрные и Маньяк; команда побеждает и посмертно.
- **Шут:** личная победа при казни; игра по умолчанию продолжается (`jesterWinEndsGame`).
- **Подрывник:** побеждает, если казнён, плюс взрыв. **Выживший и нейтральная Любовница:** живы в конце.
- **Купидон:** влюблённые только умирают вместе.
- **Ночь одновременна.** Защита: Телохранитель → лечение → щит Героя.
- **Блокировка Любовницы:** способность не срабатывает и не тратится; голос мафии не считается; заблокированный Охотник, убитый той же ночью, не стреляет.
- **«Не два раза подряд»** — у Доктора, Священника, Шантажиста, Любовницы.
- **Все чёрные роли голосуют** за жертву вдобавок к способности.
- **Голосование:** относительное большинство; ничья → одно переголосование → никто не уходит. Священник срабатывает раньше Судьи.
- **Состав:** чёрных `max(1, floor((N−1)/3))`, нейтральных до `floor(N/5)`; остаток — особые роли, потом Мирные.

## Принятые решения (этап 2)

- **Доля Мирных** (`minCiviliansShare`): по умолчанию 30% красных мест при 8+ игроках (`round(0.3 × красных)`), при меньшем числе — 0. Это ориентир: минимумы квот важнее; если долю не набрать — предупреждение `CIVILIAN_SHARE_UNMET`.
- **Адвокат без Комиссара:** после сборки состава Комиссар ставится на место другой информационной роли; если некуда — Адвоката заменяет другая чёрная роль.
- **Отдельный пакет `@mafia/protocol`** — четвёртый пакет сверх исходных трёх: общий код клиента и сервера должен быть общим.
- **Режим «Кино»** (уточнено пользователем на этапе 2.1): открытый состав плюс **личные** сцены — игрок узнаёт роль того, кто ночью подействовал на него («тебя вылечил Доктор», «у тебя ночевал Бомж»). Сцену получает только цель; в сцене роль, но не игрок. Общих рассылок про чужие действия нет. Нападения сценами не становятся; наблюдение Патрульного — тоже (он следит со стороны).
- **Убийца не раскрывается никогда, ни в одном режиме** — требование пользователя.
- **Ручной состав в скрытном режиме** виден только хосту (остальным `preset: null`, `presetHidden: true`).
- **Ведущий-наблюдатель видит всё** (уточнено на этапе 2.1): все роли, журнал целиком, чужие ходы и голоса в реальном времени, чат мафии (только чтение). Игрокам это не приходит никогда.
- **«Пустой» ход** — это `{ kind: 'pass' }`; ночь ждёт всех живых. В прогрессе — только счётчик.
- **Синхронизация «готов»** — утром после ночи и вечером после дня (под сцену приговора); ждут тех, кто в сети; 15 секунд; хост может не ждать. Вечер наступает после каждого дня, даже без казни.
- **Исключать и выходить во время партии нельзя.** Отключившегося ждут таймеры или хост.
- **Кнопка хоста `advance`** несёт `step`; устаревшая отклоняется (`STALE`).
- **Чат мафии** — только стадия `night`, только живые чёрные; история до 200 сообщений за партию.
- **Лимит попыток:** 5 с адреса и 30 на комнату за 10 минут, блокировка 10 минут.
- **Вход по WebSocket**, а не отдельным HTTP-запросом — ради экономии запросов.
- **В лобби показываются только предупреждения о составе, не зависящие от случайной раздачи.**

## Открытые вопросы

- **«Кино»: наблюдение Патрульного** сценой не становится, а проверки Комиссара, Следователя и Консильери — становятся («тебя проверял Комиссар»). Так ли нужно?
- **«Кино»: сцена при лечении впустую.** Сейчас игрок узнаёт, что его лечил Доктор, даже если нападения не было (`saved: false`).
- **Чат мафии у ведущего:** сейчас он его читает. Оставить?
- **Подрывник:** победа «за казнь» или «выживающий» со взрывом как сдерживанием?
- **Шут:** значение `jesterWinEndsGame` по умолчанию.
- **Дон:** классической проверки «ищет Комиссара» нет — добавлять ли?
- **Первая ночь:** нужна ли «ночь знакомства» без убийств?
- **Влюблённые из разных команд:** нужна ли им общая победа?
- **Бомж:** нападение на него дома срабатывает, даже если он ночует у другого.
- **Готовые наборы ролей** («классика», «хаос») — на стороне клиента?

## Известные ограничения

- Деплой не настроен. Перед ним проверить: лимит процессорного времени для PBKDF2 (100 000 итераций) на бесплатном плане; ограничение частоты создания комнат; актуальные лимиты плана.
- Узкое место бесплатного плана — записанные строки (100 000 в день): одна запись на каждое действие, примерно 350 на партию из 10 игроков.
- Счётчик попыток пароля привязан к `CF-Connecting-IP`; локально адрес у всех один (`local`).
- Ограничение частоты сообщений хранится в памяти объекта.
- Пауза перед решением Судьи выдаёт, что Судья в игре.
- Нет защиты от «вечной» партии, кроме таймеров и кнопки хоста.
- npm 12 не запускает postinstall-скрипты `esbuild` и `workerd` без явного разрешения; всё работает и без них (бинарные файлы ставятся отдельными пакетами).
- Если заданы переменные прокси, для локальных адресов нужен `NO_PROXY=127.0.0.1,localhost`.
