# @mafia/web

Веб-клиент «Мафии»: Vite + React + TypeScript + Tailwind + Framer Motion, PWA. Вёрстка в первую очередь под телефон в портретной ориентации; интерфейс на русском (структура i18n готова к другим языкам). Шрифты лежат в сборке (Fontsource), к Google Fonts клиент не обращается.

Клиент ничего не решает сам: он показывает снимки от сервера и отправляет намерения игрока. Он хранит и выводит только то, что есть в его представлении: снимок комнаты, снимок партии, журнал в своей видимости, личные сцены «Кино» и чат мафии (только у живых чёрных и ведущего).

## Запуск

Из корня репозитория:

```
npm install
npm run dev          # сервер (wrangler dev, :8787) и клиент (Vite, :5173) вместе
```

Откройте `http://localhost:5173`. Каждый «телефон» — отдельный браузер или профиль: сессия хранится в браузере (см. «Сессии»).

### С телефона в той же Wi-Fi сети

1. Запустите `npm run dev` на компьютере. Vite напечатает адреса вида `Network: http://192.168.1.63:5173/` — нужен тот, что у Wi-Fi адаптера (в Windows подписан «Беспроводная сеть»).
2. Откройте этот адрес на телефоне. Телефону нужен только Vite: запросы к серверу (`/api/…` и WebSocket) Vite сам перенаправляет на `wrangler dev` на 127.0.0.1.
3. Если не открывается — разрешите Node.js в брандмауэре Windows для частных сетей (окно с вопросом появляется при первом запуске) и проверьте, что телефон в той же сети, а не в гостевой.
4. Ссылку-приглашение (`/r/КОД`) берите из лобби — она указывает на тот же адрес.

По http в локальной сети браузер телефона не даёт Web Share API, буфер обмена и service worker (они требуют https). Кнопка «Поделиться» тогда копирует ссылку старым способом, а установка как приложение заработает после деплоя на https.

### Адрес сервера

| Переменная | Где | По умолчанию |
|---|---|---|
| `VITE_SERVER_URL` | сборка клиента | пусто — тот же источник, что и клиент |
| `MAFIA_DEV_SERVER` | `npm run dev`, `vite preview` — куда проксировать `/api` | `http://127.0.0.1:8787` |

## Команды

```
npm run test:web     # компонентные тесты (vitest + jsdom)
npm run typecheck
npm run build        # сборка в packages/web/dist
npm run e2e          # e2e через Playwright: полные партии
npm run screens      # скриншоты экранов → docs/screens/
npm run scene-shots  # скриншоты сцен (начало, середина, конец) → docs/scene-shots/
```

Витрина сцен — `http://localhost:5173/dev/scenes` (только в разработке, в сборку не попадает).

e2e и скриншоты запускают установленный Chrome (`channel: 'chrome'`) — скачивать браузеры Playwright не нужно. Другой канал: `PW_CHANNEL=chromium` (после `npx playwright install chromium`). Серверы на 8787 и 5173 поднимаются сами или переиспользуются, если уже запущены.

  i18n/                          тексты (ru.ts) и точка входа

    connection.ts                WebSocket: hello, ack/error по номеру, ping, переподключение
    session.ts                   токены в sessionStorage/localStorage

### Соединение и сессии

- Вход — первым сообщением `hello` по WebSocket: при первом входе с именем и паролем, затем по токену. Пароль нигде не сохраняется.
- Токен вкладки — в `sessionStorage` (обновление страницы = переподключение), копия — в `localStorage`, чтобы вернуться после закрытия браузера («Вернуться в комнату» на главной). Если та же сессия открыта в другой вкладке, сервер закроет старое соединение — там появится «Играть здесь» или «Войти другим игроком».
- Обрыв — переподключение с задержкой 0,5 → 10 с, плюс сразу при возвращении на вкладку. Коды 4000–4003 — окончательное закрытие с понятным текстом. Если сокет не открывается, клиент проверяет по HTTP, жива ли комната.
- `ping` раз в 25 секунд. Обратный отсчёт — по часам сервера (`deadline − serverTime`).

### EventPresenter — единая точка визуальных реакций

Всё, что «показывается» по событиям партии, идёт через `Presenter`: хранилище сообщает ему о каждом снимке, а он ставит в очередь представления:

| Представление | Когда | По завершении |
|---|---|---|
| `roleReveal` | начало партии (или обновление страницы до первого хода) | — |
| `nightReport` | стадия `morning`; и в конце партии, если её закончила ночь | `ready` |
| `verdict` | стадия `evening`; и в конце партии, если её закончила казнь | `ready` |
| `finale` | стадия `ended` | — |

Отчёты строятся из журнала функциями `digest.ts` («такты»: смерть, спасение, молчание, проверка, сцена «Кино», итоги голосования…), разделёнными на общее и личное. Рендерер выбирается по реестру `renderers`. Кинематографичный слой (этап 4) заменит рендереры, не трогая логику «когда и что показать». Ведущему отчёты не показываются — он видит журнал целиком, а `ready` от него уходит сам.

### Сцены (этап 4)

```
src/scenes/
  types.ts            контракт сцены: props (presentation, view, display, prefs, quality, live…) + onComplete
  registry.ts         реестр: представление → ленивый компонент сцены (пока сцены нет — простой экран этапа 3)
  SceneStage.tsx      тап — пропуск; у хоста во время общих сцен — «Пропустить у всех»
  clock.ts            часы сцен: главный таймлайн GSAP, скорость, пауза, кадр, перемотка, пропуск
  useSceneTimeline.ts таймлайн в gsap.context + регистрация в часах
  fx/                 частицы на canvas 2D — чистая функция времени таймлайна (перематываются вместе со сценой)
  audio/sfx.ts        звуки: синтез через Web Audio (OfflineAudioContext → WAV) + Howler; TODO — записанные звуки
  deck/DeckScene.tsx  «Колода» — выдача роли
src/settings/         личные настройки устройства (звук, вибрация, «Уменьшить анимацию», «Мягкие эффекты»),
                      авто-качество (слабое устройство, просадка кадров), вибрация
src/dev/              витрина /dev/scenes и данные для неё (партия, собранная движком)
```

- Каждая сцена — изолированный компонент с одним главным таймлайном GSAP. Анимации — только transform и opacity; карточки — Framer Motion (переворот, голограмма), частицы — canvas 2D.
- Сцены, GSAP и Howler грузятся лениво: начальный бандл вырос на ~2 КБ gzip, «Колода» — отдельный кусок ~46 КБ gzip.
- Качество: `full` — всё; `lite` (слабое устройство или просадка кадров во время сцены) — меньше частиц, без высокой плотности пикселей; `reduced` («Уменьшить анимацию» или системная настройка) — короткие переходы без полётов и частиц.
- Тап по сцене пропускает анимацию к конечному кадру; кнопки внутри сцены тап не перехватывают. Если игра у всех пошла дальше (хост нажал «Пропустить у всех» или вышло время синхронизации), сцена сразу переходит к концу.
- Витрина `/dev/scenes`: сцена, роль, режим показа, «Мягкие эффекты», «Уменьшить анимацию», звук, скорость ×1/×0.5/×0.25, пауза, ±1 кадр, ползунок. Параметры адреса: `scene`, `role`, `display`, `soft`, `reduce`, `sound`, `speed`, `at` (доля) или `t` (секунды), `ui=0`.

**Карточки.** Иллюстрация роли — `src/assets/cards/<roleId>.webp` (1024×1536, без рамки и текста), рубашка — `back.webp`. Рамку ар-деко, табличку с названием и свечение рисует код поверх арта или процедурной заглушки (гильош, лучи, медальон с эмблемой). `HoloCard` — наклон за пальцем и гироскопом (на iOS разрешение спрашивается по первому касанию), блик, радужная плёнка, параллакс слоёв `.holo-layer`.

**«Колода».** Колода внизу → тап → карта по дуге с вращением в центр → переворот со вспышкой и искрами цвета команды → название по буквам и описание → карточка-голограмма. Мафия видит напарников маленькими карточками. «Спрятать» возвращает карту в колоду и закрывает сцену. Дальше роль смотрится удержанием («Моя роль»).

### Приватность на столе

Телефоны лежат на столе, поэтому интерфейс не выдаёт роль тому, кто заглянул через плечо:

- роль видна только пока карточку удерживают пальцем («Моя роль» внизу экрана);
- ночной ход у всех одинаков по виду: заголовок «Ваш ночной ход», сетка игроков, «Пропустить» и «Сделать ход». У кого способности нет, выбор — заметка для себя, на сервер уходит «пустой» ход;
- в сетках выбора и в списке стола роли живых не показываются (свою и сообщников — тоже); сделанный ход скрыт, пока не нажать на глаз;
- личные итоги ночи — в карточке «Только для вас», которая открывается по нажатию.

«Блокнот» в шапке есть у всех и выглядит одинаково: у чёрных за ним чат команды и голоса команды за жертву, у остальных — личные заметки (только на этом устройстве, стираются с новой партией). О новом сообщении команды сообщает только вибрация — значок на кнопке выдал бы мафию.

### Карточка роли

`components/RoleCard.tsx`: пропорции 2:3, рубашка и лицо, переворот. Иллюстрация берётся из `src/assets/cards/<roleId>.webp`, если файл есть (список известен при сборке — лишних запросов нет); иначе — процедурная заглушка в цвете команды с эмблемой роли. Красные — алые, чёрные — чёрно-золотые, нейтральные — серебристо-изумрудные.

### Дизайн-система

`styles.css` (`@theme` Tailwind 4): нуар, золото и бордо, цвета команд, шрифты Playfair Display (заголовки) и Manrope (текст). Палитра фазы задаётся атрибутом `data-phase="night|day|ended"` на контейнере: ночью — холодная синевато-чёрная с лунным серебром, днём — тёплая коньячная с янтарём.

### PWA

`public/manifest.webmanifest`, иконки (PNG и SVG) и `public/sw.js`: оболочка приложения из кэша, `/api/*` — только сеть. Service worker регистрируется только в собранном клиенте и в защищённом контексте (https или localhost).
