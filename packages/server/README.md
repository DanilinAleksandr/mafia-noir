# @mafia/server

Сервер «Мафии»: Cloudflare Worker + Durable Objects с WebSocket Hibernation. Одна комната — один Durable Object. Вся игровая логика выполняется на сервере через `@mafia/engine`; клиент получает только своё представление и события в своей видимости.

Работает локально без входа в Cloudflare и без доступа в интернет. Деплой пока не настроен — это отдельный этап.

## Запуск

Из корня репозитория (нужен Node 22.12 или новее):

```
npm run dev        # сервер (http://127.0.0.1:8787) и веб-клиент (http://localhost:5173) вместе
npm run dev:server # только сервер (wrangler dev)
npm run bots       # партия ботов с журналом в консоли (сам поднимет сервер)
npm run test:server
npm run typecheck
```

Откройте `http://127.0.0.1:8787/` — там отладочная страница без оформления: создать комнату, войти, сыграть. Каждая вкладка браузера — отдельный игрок.

Боты:

```
npm run bots                                          # своя партия на своём локальном сервере
npm run bots -- --players 10 --seed 5 --display cinema --games 2 --quiet
npm run bots -- --url http://127.0.0.1:8787           # партия на уже запущенном сервере
npm run bots -- --url http://127.0.0.1:8787 --join ABCDE --password 1234 --count 4
                                                      # подсадить ботов в вашу комнату
```

Последний вариант удобен для ручной проверки: создаёте комнату на отладочной странице, подсаживаете ботов и играете с ними.

**Про сеть.** `wrangler dev` работает в локальном режиме: Durable Objects и хранилище эмулируются на вашей машине (данные — в `packages/server/.wrangler/`). Отправка статистики выключена в `wrangler.jsonc`. Если в системе заданы переменные прокси, wrangler предупредит о них; для обращений к `127.0.0.1` задайте `NO_PROXY=127.0.0.1,localhost`.

## Устройство

```
src/
  index.ts        Worker: маршруты, создание комнаты, выдача отладочной страницы
  room.ts         Durable Object комнаты — вся логика сервера
  state.ts        состояние комнаты в хранилище, лимиты сервера
  game-view.ts    стадия партии, состав без владельцев, сцены режима «Кино»
  crypto.ts       PBKDF2, токены, случайные значения (WebCrypto)
  debug-page.ts   отладочная страница
tools/
  bot.ts          «мозг» бота: по своему снимку решает, что отправить
  bots.ts         скрипт `npm run bots`
test/             интеграционные тесты внутри workerd (@cloudflare/vitest-plugin)
wrangler.jsonc    конфигурация Worker и Durable Object
```

Общие типы сообщений, проверка входящих и коды ошибок лежат в отдельном пакете `@mafia/protocol` — его же будет использовать веб-клиент.

**Хранение.** Всё состояние комнаты — один JSON под ключом `room`: участники, настройки, `GameState` движка, чат мафии, счётчики попыток. Durable Object может уснуть между сообщениями; при пробуждении он читает состояние из хранилища. О соединении известно только то, что записано в его attachment (id участника и адрес).

**Таймеры.** У объекта один будильник. Он заводится на ближайший из сроков: таймер стадии, утренняя синхронизация, передача прав хоста, проверка простоя.

**Часы в тестах.** У объекта есть поле `skewMs` — сдвиг часов; тесты «перематывают» время и вручную запускают будильник.

## Комнаты

| Что | Как |
|---|---|
| Код | 5 символов из `ABCDEFGHJKMNPQRSTUVWXYZ23456789` — без `0`, `O`, `1`, `I`, `L`. Регистр при вводе не важен. |
| Ссылка | `/r/КОД` |
| Пароль | Обязателен, 1–64 символа. Хранится только хеш: PBKDF2-SHA256, 100 000 итераций, соль 16 байт. |
| Неверные попытки | 5 с одного адреса за 10 минут → блокировка адреса на 10 минут; 30 на всю комнату → блокировка новых входов на 10 минут. Переподключению по токену блокировка не мешает. |
| Токен | 192 случайных бита, выдаётся один раз при входе; в хранилище лежит его SHA-256. По токену участник возвращается под тем же id. |
| Участники | До 20. Имя 1–20 символов, уникально в комнате без учёта регистра. |
| Одно соединение на участника | Новое соединение с тем же токеном закрывает старое (`REPLACED`). |
| Онлайн-статус | Участник в сети, пока у него открыт WebSocket. Статус виден всем в снимке комнаты. |
| Хост | Создатель комнаты. Может менять настройки, начинать игру, исключать (не во время партии), передавать права, жать «дальше», возвращать всех в лобби. |
| Автопередача прав | Хост не в сети дольше 2 минут → права получает первый по списку участник, который в сети. Если в сети никого нет — первый, кто вернётся. |
| Режим хоста | `player` — хост играет; `narrator` — «ведущий-наблюдатель»: роли не получает, зато видит всё (см. ниже). |
| После старта | Новые участники не входят (`ROOM_STARTED`). Переподключение работает всегда. |
| Простой | Комната удаляется через 6 часов без действий. Она же удаляется сразу, когда выходит последний участник. |

## Настройки комнаты

Меняет хост, только в лобби (`settings`). Видны всем.

| Настройка | По умолчанию | Смысл |
|---|---|---|
| `hostMode` | `player` | `player` или `narrator`. |
| `display` | `stealth` | Режим показа событий, см. ниже. |
| `timers.night`, `timers.discussion`, `timers.day`, `timers.decision` | `null` | Таймеры стадий в секундах (10–3600): ночь, обсуждение, голосование, решение игрока. `null` — выключен. |
| `rules` | правила движка по умолчанию | Все правила `@mafia/engine`. |
| `composition.roles`, `.quotas`, `.minCiviliansShare`, `.preset` | — | Включение ролей и лимиты копий, квоты, доля Мирных, ручной состав. |

В снимке комнаты есть `startIssues` — почему сейчас нельзя начать (мало игроков, квоты не сходятся) — и `startWarnings`.

### Режимы показа событий

| Режим | Что получают клиенты |
|---|---|
| `stealth` — «Скрытный» | Только то, что игрок вправе видеть: своё представление и события в своей видимости. |
| `open` — «Открытый состав» | То же, плюс `game.composition` — список ролей в партии с количеством, в порядке каталога, без владельцев. |
| `cinema` — «Кино» | Открытый состав, плюс каждый игрок узнаёт **роль** того, кто ночью подействовал лично на него. Кто именно это был — не сообщается. |

**Личные сцены «Кино».** После ночи игрок получает `scenes` — по одной на каждую способность, применённую к нему: `{ id, round, ability, role, saved }`. Например, `{ ability: 'heal', role: 'doctor', saved: true }` — «тебя вылечил Доктор», `{ ability: 'stay', role: 'hobo' }` — «у тебя ночевал Бомж», `{ ability: 'block', role: 'mistress' }` — «тебя заблокировала Любовница». Правила:

- сцену получает только тот, на кого подействовали; общих рассылок про чужие действия нет;
- в сцене есть роль, но нет игрока;
- `saved: true` — именно эта способность спасла получателя от нападения этой ночью (лечение, зелье, охрана);
- заблокированная способность не сработала — сцены нет;
- наблюдение Патрульного сценой не становится: он следит со стороны;
- **нападения сценами не становятся никогда.**

**Убийца не раскрывается ни в одном режиме.** Кто именно убил, видит только сам убийца (у мафии — своя команда) и ведущий-наблюдатель. Остальные получают событие `death` без `actors`. Это относится и к выстрелу Охотника, и к взрыву Подрывника.

**Ручной состав и скрытный режим.** Если хост задал `composition.preset`, в режиме `stealth` его видит только хост: остальным в настройках приходит `preset: null` и флаг `presetHidden: true`. Иначе настройки раскрывали бы состав партии.

## Ход партии

Сервер добавляет к фазам движка свои стадии (`game.stage`):

| Стадия | Что происходит | Чем заканчивается |
|---|---|---|
| `night` | Принимаются ночные ходы. | Сходили все живые; таймер ночи; кнопка хоста. |
| `decision` | Игра ждёт решения одного игрока (Охотник, Подрывник, Судья). | Решение принято; таймер решения; кнопка хоста (решение по умолчанию). |
| `morning` | Ночь разрешена; клиенты показывают её итоги и шлют `ready`. | Готовы все, кто в сети; 15 секунд; кнопка хоста. |
| `discussion` | Обсуждение. Голоса ещё не принимаются. | Кнопка хоста («Начать голосование»); таймер обсуждения. |
| `day` | Голосование: принимаются голоса. | Проголосовали все живые; таймер голосования; кнопка хоста. |
| `evening` | День закончен; клиенты показывают приговор и шлют `ready`. | Готовы все, кто в сети; 15 секунд; кнопка хоста. |
| `ended` | Партия окончена, все роли открыты. | Хост возвращает всех в лобби (`toLobby`). |

**«Пустой» ход.** Ночью ход делают все живые, в том числе те, кому делать нечего: для них ход — `{ kind: 'pass' }`. Ночь не кончится, пока не сходят все, поэтому по скорости ответа роль не вычислить. Клиенту стоит показывать всем одинаковое по виду действие. В `game.progress` — только число сходивших, без имён.

**Отложенные решения.** Решение (`view.decision`) приходит только тому, от кого его ждут. Остальные получают стадию `decision`, `view.waitingForDecision: true` и больше ничего: ни чьё решение, ни какого вида.

**Утро и вечер.** Это паузы под анимации. После ночи движок уже в фазе дня, но сервер не принимает голоса, пока стадия `morning`: клиент показывает итоги ночи и шлёт `ready`. После дня — то же самое со стадией `evening`: движок уже в следующей ночи, но ходы и чат мафии закрыты, пока клиенты показывают сцену приговора. Вечер наступает после каждого дня, даже если никого не казнили; если показывать нечего, клиент шлёт `ready` сразу. Отключившихся не ждут. Таймеры дня и ночи отсчитываются с их начала, а не с конца предыдущей стадии. Если ночь или казнь закончили партию, паузы нет — сразу `ended`.

**Ведущий-наблюдатель.** В режиме `narrator` хост не играет и видит всё в реальном времени: все роли, журнал целиком (результаты проверок, кто кого убил), а в `view.backstage` — чужие ночные ходы и голоса по мере их подачи, а также от кого и какого решения ждёт игра. Он читает чат мафии, но писать в него и ходить не может. Его снимок — это `viewFor(state, null, { seeAll: true })`. Игрокам всё это не приходит никогда: `backstage` у них всегда `null`. Если права хоста посреди партии перешли к игроку, видеть всё он не начинает; прежний ведущий остаётся наблюдателем.

**Обсуждение.** День начинается с обсуждения (`discussion`): голоса не принимаются, пока хост не откроет голосование (`advance`) или не истечёт таймер обсуждения. Переголосование при ничьей идёт сразу, без нового обсуждения.

**Кнопка хоста.** `advance` продвигает игру, никого не дожидаясь: разрешает ночь, открывает голосование, подводит голосование, применяет решение по умолчанию, начинает день. В сообщении передаётся `step`; если ситуация уже изменилась, сервер ответит `STALE` и ничего не сделает — двойное нажатие не «проскочит» следующую стадию.

**Чат мафии.** Доступен только в стадии `night` и только живым чёрным: и отправка, и получение. Погибший мафиози выпадает из чата. История (до 200 сообщений за партию) приходит при переподключении — тоже только живым чёрным. Ведущий-наблюдатель чат читает, но не пишет.

**Отключившиеся игроки.** Партия их ждёт. Без таймеров дальше игру двигает хост.

## Протокол

Версия протокола — `PROTOCOL_VERSION = 2` (в версии 2 появилась стадия `discussion` и таймер `timers.discussion`). Все типы — в `@mafia/protocol` (`src/messages.ts`).

### HTTP

| Запрос | Тело | Ответ |
|---|---|---|
| `POST /api/rooms` | `{ name, password, hostMode? }` | `201 { code, memberId, token }` |
| `GET /api/rooms/:code` | — | `200 { code, stage, members, joinable }` или `404` |
| `GET /api/rooms/:code/ws` | WebSocket | `101` или `404` |

Ошибки HTTP: `{ "error": { "code", "message" } }`. CORS открыт для любого источника: авторизация идёт токеном в сообщении, а не куками.

### WebSocket

Каждое сообщение — JSON с полем `t`. Отдельно ходят строки `ping` → `pong`: сервер отвечает на них, не просыпаясь, так что клиент может держать соединение живым бесплатно.

Первое сообщение клиента — `hello`:

```jsonc
{ "t": "hello", "v": 1, "token": "…" }                       // переподключение
{ "t": "hello", "v": 1, "name": "Аня", "password": "1234" }  // первый вход
```

В ответ приходит `welcome` — всё, что нужно, чтобы нарисовать экран: снимок комнаты, снимок партии, весь журнал событий в видимости участника, сцены, чат мафии и (только при первом входе) токен. Отказ во входе — `error` и закрытие соединения с кодом 4000.

Любое сообщение клиента может нести номер `id`. Тогда сервер ответит `{ "t": "ack", "re": id, "rev": … }` или `{ "t": "error", "re": id, … }`.

#### Клиент → сервер

| `t` | Поля | Кто и когда |
|---|---|---|
| `hello` | `v`, затем `token` либо `name` и `password` | Первое сообщение. |
| `settings` | `patch` | Хост, в лобби. `roles` и `quotas` заменяются целиком, остальное — по полям. |
| `kick` | `memberId` | Хост, не во время партии. |
| `transferHost` | `memberId` | Хост. |
| `leave` | — | Любой, не во время партии. |
| `start` | — | Хост, в лобби. |
| `toLobby` | — | Хост, во время партии или после неё. |
| `night` | `action` — `NightAction` движка | Живой игрок, стадия `night`. |
| `vote` | `target` (id или `null`) | Живой игрок, стадия `day`. |
| `decision` | `decision` — `Decision` движка | Тот, от кого ждут решения. |
| `ready` | `step` | Любой, стадии `morning` и `evening`. Опоздавший `ready` молча игнорируется. |
| `advance` | `step` | Хост, во время партии. |
| `chat` | `text` (1–300 символов) | Живой чёрный, стадия `night`. |

#### Сервер → клиент

| `t` | Поля | Когда |
|---|---|---|
| `welcome` | `v`, `memberId`, `token`, `room`, `game`, `history`, `scenes`, `chat` | В ответ на `hello`. |
| `room` | `room` — `RoomSnapshot` | Изменились участники, онлайн, хост, настройки, стадия комнаты. |
| `game` | `game` — `GameSnapshot`, `events`, `scenes` | Изменилась партия. `events` — новые события в видимости получателя, `scenes` — его новые личные сцены («Кино»). |
| `chat` | `message` | Новое сообщение чата мафии. |
| `ack` | `re`, `rev` | Запрос с номером `re` выполнен. |
| `error` | `code`, `message`, `re` | Запрос отклонён. |
| `bye` | `code`, `message` | Сервер закрывает соединение. |

`GameSnapshot`: `rev`, `step`, `stage`, `deadline`, `serverTime`, `display`, `composition`, `progress` и `view` — представление движка (`PlayerView` без журнала). Журнал клиент собирает сам: `history` из `welcome` плюс `events` из каждого `game`.

- `rev` — номер рассылки, общий для `room` и `game`. За одно входящее сообщение каждому клиенту уходит не больше одного `room` и одного `game`.
- `step` — номер шага партии: растёт при каждом разрешении (ночь, голосование, решение, начало дня). Его передают в `ready` и `advance`.
- `deadline` и `serverTime` — в миллисекундах по часам сервера; по разнице клиент рисует обратный отсчёт без оглядки на свои часы.

#### Коды закрытия

| Код | Причина | Переподключаться |
|---|---|---|
| 1000 | Обычное закрытие. | да |
| 4000 | Отказ во входе или нарушение протокола до входа. | нет, сначала исправить данные |
| 4001 | Исключён хостом или вышел сам. | нет |
| 4002 | Соединение заменено новым. | нет |
| 4003 | Комната удалена. | нет |

#### Ошибки

У каждой ошибки есть код и текст по-русски (`ERROR_MESSAGES` в `@mafia/protocol`). Текст можно показывать как есть; сервер иногда уточняет его («Неверный пароль. Осталось попыток: 3»).

| Группа | Коды |
|---|---|
| Разбор | `BAD_MESSAGE`, `TOO_LARGE`, `RATE_LIMITED`, `PROTOCOL_VERSION` |
| Вход | `NOT_AUTHENTICATED`, `ALREADY_AUTHENTICATED`, `ROOM_NOT_FOUND`, `ROOM_FULL`, `ROOM_STARTED`, `ROOM_BUSY`, `WRONG_PASSWORD`, `TOO_MANY_ATTEMPTS`, `BAD_TOKEN`, `BAD_NAME`, `NAME_TAKEN`, `BAD_PASSWORD` |
| Права и состояние | `NOT_HOST`, `WRONG_STAGE`, `STALE`, `UNKNOWN_MEMBER`, `BAD_SETTINGS`, `CANNOT_START`, `NOT_PLAYING`, `CHAT_FORBIDDEN` |
| Закрытие | `KICKED`, `LEFT`, `REPLACED`, `ROOM_CLOSED` |
| Игра (ошибки движка) | `GAME_WRONG_PHASE`, `GAME_DECISION_PENDING`, `GAME_NO_DECISION`, `GAME_UNKNOWN_PLAYER`, `GAME_PLAYER_DEAD`, `GAME_INVALID_ACTION`, `GAME_INVALID_TARGET`, `GAME_INVALID_CONFIG`, `GAME_INVALID_COMPOSITION` |
| Прочее | `INTERNAL` |

### Проверка входящих

Всё, что пришло из сети, проходит `parseClientMessage`: размер (до 16 КБ), JSON, тип, каждое поле. Лишние поля отбрасываются, неизвестные типы и значения отклоняются. Настройки проверяются поимённо: неизвестное правило, роль или квота — ошибка с объяснением. Дальше сервер работает только с проверенным значением. Не больше 40 сообщений за 10 секунд от одного участника.

## Что гарантирует сервер

- Игроку уходит `viewFor(state, его id)` и проекции событий для него — и ничего сверх этого.
- «Видеть всё» достаётся только ведущему-наблюдателю — участнику, который не играет в партии. Не играть может только тот, кто был хостом в режиме `narrator` на момент старта.
- Убийца не раскрывается никому, кроме него самого, его чёрной команды и ведущего.
- Личные сцены «Кино» уходят только тому, на кого подействовали, и называют роль, а не игрока.
- Чужие ночные действия, голоса (в тайном режиме) и решения не приходят никому, кроме автора.
- О том, от кого ждут решения, остальные не узнают.
- Чат мафии приходит только живым чёрным.
- Пароль и токены не хранятся в открытом виде и никому не отправляются (токен — только своему владельцу, один раз).

## Экономия запросов

Лимиты бесплатного плана (по документации Cloudflare на момент этапа): 100 000 запросов к Workers в день; у Durable Objects — 100 000 запросов в день, 13 000 ГБ·с работы и 100 000 записанных строк в день.

Что сделано:

- **Вход — одним запросом.** Имя и пароль отправляются первым сообщением по WebSocket, отдельного HTTP-запроса нет. Создание комнаты — два запроса (POST и WebSocket).
- **Никакого опроса.** Клиент ничего не запрашивает повторно: сервер сам присылает изменения. Исходящие сообщения бесплатны.
- **Входящие сообщения WebSocket** считаются как 1/20 запроса, а `ping` — бесплатно и без пробуждения объекта.
- **Спячка.** Между сообщениями объект не занимает оплачиваемое время: соединения держит платформа.
- **Одна запись на действие.** Состояние — один ключ; сообщение, которое ничего не меняет, ничего не пишет. Будильник переставляется, только когда меняется ближайший срок. Отметка активности для отсчёта простоя не пишется отдельно.

Грубая оценка: партия на 10 игроков — около 300 входящих сообщений, то есть примерно 15 запросов к Durable Object плюс 11 подключений, и около 350 записанных строк. Узкое место — записанные строки: их хватает примерно на 250–280 таких партий в день.

| Файл | Что проверяет |
|---|---|

| `game.test.ts` | Ночь с «пустыми» ходами, таймер и кнопка хоста; утренняя и вечерняя синхронизация; день; конец партии и возврат в лобби; отложенные решения и их таймаут; чат мафии; режимы показа, личные сцены «Кино»; ведущий-наблюдатель; спячка объекта посреди партии; ограничение частоты сообщений. |
| `bots.test.ts` | Полные партии ботов в шести конфигурациях, с отключениями и переподключениями, несколько партий подряд — под «прослушкой». Отдельно — проверка, что прослушка ловит утечки. |

**Прослушка** (`test/wiretap.ts`) перехватывает **все** сообщения каждого клиента и после каждого действия проверяет их семью независимыми способами:

1. снимок и события в сообщении в точности равны `viewFor` и проекциям движка для этого получателя;
2. роль игрока видна, только если получатель вправе её знать (оракул написан отдельно от движка);
3. названия скрытых ролей не встречаются в сыром тексте сообщения нигде;
4. чат мафии приходит только живым чёрным;
5. чужие токены и служебные поля (`tokenHash`, `salt`, `rng`, `visibility`) не уходят никому;
6. личные сцены «Кино» приходят только тому, на кого подействовали, называют роль, но не игрока, и никогда не описывают нападение;
7. «закулисье» (чужие ходы и голоса) игроку не приходит никогда.

**Ведущему разрешено, игрокам — нет.** Для ведущего-наблюдателя прослушка требует точного совпадения с `viewFor(…, { seeAll: true })` и пропускает проверки 2–4 и 7; служебные секреты не положены и ему. Ведущим прослушка считает только того, кто не играет в партии, начатой в режиме `narrator`: любой другой получатель такого снимка — утечка.

То, что прослушка работает, проверено дважды. В тестах лежат подделанные сообщения (чужая роль, полное событие вместо скрытного, чужой снимок, чат мирному, чужой токен, чужая сцена, сцена с нападавшим, «закулисье» и снимок ведущего у игрока) — она должна поймать каждое. А при разработке в сервер временно вносились тринадцать настоящих утечек (всем уходит чужой снимок; события без проекции; чат мафии всем; состав в скрытном режиме; ручной состав всем; вид ведущего всем игрокам или только чёрным; чужие сцены; сцена с убийцей и другие) — тесты поймали все тринадцать.

## Отладочная страница

`GET /` и `GET /r/:code`. Один HTML-файл без стилей: формы создания и входа, список участников, кнопки хоста, поле для изменения настроек (JSON), ночной ход, голосование, решения, кнопки «готов» утром и вечером, чат мафии, личные сцены «Кино», «закулисье» ведущего, журнал событий и сырые сообщения сервера. Токен хранится в `sessionStorage`, поэтому каждая вкладка — отдельный игрок, а обновление страницы — это переподключение.

Страницу отдаёт сам Worker (один запрос). Веб-клиент живёт отдельно (`packages/web`, в разработке — http://localhost:5173), а отладочная страница остаётся на адресе сервера как эталон поведения.

## Ограничения и принятые решения

- **Ведущий-наблюдатель видит всё** — значит, ему приходится доверять. Режим рассчитан на отдельное устройство ведущего, а не на общий экран в комнате.
- **Исключать и выходить во время партии нельзя**: движок не умеет убирать игрока посреди игры. Отключившегося ждут таймеры или хост.
- **Вечер наступает после каждого дня**, а не только после казни: клиенту проще, когда порядок стадий всегда один.
- **Сцену «Кино» получает и тот, кого лечили впустую** (нападения не было): тогда `saved: false`.
- **Счётчик попыток привязан к адресу** из заголовка `CF-Connecting-IP`; локально адрес у всех один — `local`.
- **Создание комнат не ограничено по частоте.** Для деплоя понадобится ограничение.
- **Ограничение частоты сообщений хранится в памяти** и сбрасывается, когда объект засыпает; для защиты от флуда этого достаточно, потому что флуд не даёт объекту уснуть.
- **Пауза перед решением Судьи** выдаёт, что Судья в игре: стадия `decision` наступает только когда есть кому решать.
- **PBKDF2 считается внутри Durable Object.** На бесплатном плане нужно проверить на деплое, укладывается ли это в лимит процессорного времени.
